## 1. 文档目的与阅读结论

### 1.1 文档目的

本文档将项目说明书中的架构信息、页面说明、API 约定和当前源码实现统一整理为面向产品、研发、测试和项目接手人的 PRD，明确：

1. 产品定位、目标用户和业务价值；
2. 完整功能地图及各功能的产品需求；
3. 当前已完成、部分完成、未完成的范围；
4. 页面、接口、数据模型和关键业务流程；
5. 非功能要求、验收标准、风险和后续迭代顺序。

### 1.2 当前版本结论

辰光 Agent 平台当前已经形成一个可运行的企业内部 AI 能力管理后台雏形：前端 React 页面体系较完整，后端 FastAPI 已搭建统一 REST API、JWT 登录、RBAC 基础、MySQL/Redis/MinIO 基础设施，以及 Provider、Model、Prompt、Knowledge、Tool、Agent 六大核心模块的 CRUD 与部分操作 API。

当前项目的主要矛盾不是“页面缺失”，而是“展示层和管理层已较完整，AI 运行时和生产级数据闭环尚未完成”。尤其是知识库文档解析/切片/Embedding/向量检索、供应商真实连通性校验、工具真实执行、Agent 实际启动运行、对话日志/统计/告警等模块，前端或服务层虽有页面和类型设计，但后端能力仍未完全落地。

## 2. 产品概述

### 2.1 产品定位

辰光 Agent 平台是面向企业内部研发、运营和管理人员的 AI 应用基础管理平台，用于集中接入大模型供应商，配置模型、Prompt、知识库和工具，并以 Agent 为业务编排单元进行测试、发布、版本管理和运营监控。

产品目标是将分散的模型调用、Prompt 调试、RAG 配置、工具调用和 Agent 运行管理统一收敛到一个可审计、可复用、可扩展的平台中。

### 2.2 产品边界

**本产品负责：**

- AI 供应商和模型的配置管理；
- Agent 的配置、版本、测试与状态管理；
- Prompt 模板及版本管理；
- 知识库、文档、分段和检索能力；
- 工具注册、参数定义和工具测试；
- 对话记录、调用统计、费用分析和效果评估；
- 用户、角色、权限、API Key、审计、告警和全局配置。

**本产品暂不等同于：**

- 面向终端消费者的聊天产品；
- 完整的模型训练或微调平台；
- 完整的向量数据库产品；
- 完整的任务编排/工作流引擎；
- 生产级多租户计费系统。

### 2.3 核心价值

| 价值 | 说明 |
|---|---|
| 统一接入 | 对不同厂商模型提供统一配置入口，降低接入和切换成本 |
| 快速构建 | 通过 Prompt、知识库和工具组合快速构建 Agent |
| 可控发布 | 通过版本、发布、回滚和启停机制降低变更风险 |
| 可观测 | 记录调用、Token、费用、延迟、成功率和告警 |
| 安全治理 | 通过 RBAC、API Key、审计和配置管理约束 AI 能力使用 |

## 3. 用户与使用场景

### 3.1 用户角色

| 角色 | 主要职责 | 典型权限 |
|---|---|---|
| 平台超级管理员 | 负责平台初始化、用户权限、全局配置和安全治理 | 全部模块、用户/角色/权限、系统设置 |
| AI 平台管理员 | 负责模型、供应商、Prompt、知识库、工具和 Agent 的日常管理 | 核心 AI 资源的增删改查、测试、发布 |
| Agent/应用开发者 | 负责创建和调试 Agent、Prompt、知识库和工具 | 创建编辑自己的资源，测试和提交发布 |
| 运营/分析人员 | 关注调用量、成本、质量和告警 | 工作台、对话日志、数据统计、导出 |
| 只读审计人员 | 查看资源和审计记录，不修改配置 | 只读访问 |

> 当前源码已具备用户、角色、权限实体和角色分配接口，但前端路由级/按钮级权限控制仍需补齐，角色权限的产品语义应在后续版本固化。

### 3.2 典型场景

1. 管理员录入一个模型供应商和多个模型，配置 API Endpoint、密钥、上下文窗口及价格；
2. 开发者创建 Prompt，保存草稿，发布多个版本并在需要时回滚；
3. 开发者创建知识库，上传文档，等待处理完成后进行分段校对和检索测试；
4. 开发者注册一个 HTTP API 或 Function Calling 工具，在线测试参数和响应；
5. 开发者创建 Agent，选择模型、Prompt、知识库和工具，进行对话调试，发布后启用；
6. 运营人员查看 Agent 调用量、Token、费用、延迟、成功率和异常告警；
7. 审计人员查看用户操作、资源变更和 API 调用轨迹。

## 6. 详细功能需求

## 6.1 登录、认证与账户

### 6.1.1 登录 ✅

**入口**：`/login`

**需求：**

- 输入用户名、密码、图形验证码；
- 获取并刷新验证码；
- 登录成功后获取 JWT Bearer Token；
- Token 持久化到浏览器本地存储；
- 后续请求自动携带 `Authorization: Bearer <token>`；
- 未登录访问受保护路由时跳转登录页；
- 登录失败展示后端错误消息；
- 退出登录清理本地认证状态。

**已实现：** FastAPI 登录接口、验证码接口、前端 AuthGuard、Token 存储与自动注入。

**待完善：** Token 过期刷新、登录失败次数限制、密码复杂度、异地登录/会话管理、生产环境密钥安全。

### 6.1.2 个人资料与账户设置 🟡

**需求：**

- 查看用户名、邮箱、角色、最近登录时间；
- 修改密码；
- 配置通知偏好和界面偏好；
- 支持安全设置入口。

**现状：** 前端页面和交互说明已存在，后端仅稳定提供当前用户基础信息；密码修改、通知设置和安全策略尚不完整。

## 6.3 Agent 管理

**入口**：`/agents`

### 6.3.1 Agent 列表 ✅/🟡

**功能：**

- 分页查询 Agent；
- 按关键词、状态、类型筛选；
- 查看名称、描述、类型、状态、当前版本、调用量、成功率；
- 创建、编辑、删除；
- 启动/停止；
- 进入详情、测试、版本、监控。

**后端已具备：** `POST/GET/PUT/DELETE /api/v1/agents`、`/{id}/start`、`/{id}/stop`。

### 6.3.2 创建/编辑 Agent ✅

**表单字段：**

- 基本信息：名称、描述、Agent 类型；
- 模型配置：供应商/模型、温度、最大 Token、上下文配置；
- Prompt 配置：选择 Prompt 或编辑系统提示词；
- 知识库配置：关联知识库、Top K、相似度阈值、检索策略；
- 工具配置：勾选可用工具、调用策略；
- 高级配置：超时、重试、并发、记忆窗口等。

配置统一存入 Agent `config` JSON，模型通过 `model_id` 关联。

### 6.3.3 Agent 测试/调试 🟡

**功能：**

- 多轮对话输入与流式输出；
- 查看 Prompt、模型参数、知识库命中、工具调用等调试信息；
- 清空当前会话；
- 展示错误、延迟和 Token。

**现状：** 模型测试页已有 FastAPI + SSE 流式通信和 Redis 30 分钟短期记忆；Agent 页面和数据结构已有，但 Agent 的实际运行时编排、RAG 调用、工具调用未落地。

### 6.3.4 版本管理 ✅/🟡

- 发布当前配置为新版本；
- 记录版本号、变更说明、发布人、发布时间；
- 查看版本列表；
- 回滚至历史版本；
- 发布后默认进入未运行状态，需显式启动。

后端已提供发布、版本列表、回滚接口；版本差异对比和发布前校验需完善。

### 6.3.5 监控 🔴

计划展示：调用量、成功率、平均延迟、Token、费用、错误分布、时间趋势。

当前前端页面存在，但后端缺少实时指标采集、查询和聚合实现。

### 6.3.6 Agent 关键验收标准

- Agent 未配置模型时不可发布；
- 发布版本必须保留不可变配置快照；
- 回滚后当前版本、配置和状态一致；
- 停止后不得接受新的运行请求；
- 测试会话能稳定输出流式结果并正确归属消息；
- 每次运行产生可查询的调用记录、Token、耗时和错误信息。

## 6.6 知识库（RAG）管理

**入口**：`/knowledge`

### 6.6.1 知识库管理 ✅

- 创建、编辑、删除知识库；
- 配置 Embedding 模型；
- 配置分段方式、分段大小、重叠长度；
- 配置检索策略、Top K、相似度阈值；
- 展示文档数、分段数、处理状态。

### 6.6.2 文档管理 🟡

**支持目标格式：** PDF、DOCX、Markdown、TXT、HTML/HTM，以及产品说明中规划的图片 OCR 类型。

**已实现：**

- Multipart 文档上传；
- 文件类型校验；
- 文件写入 MinIO `knowledge-docs` bucket；
- 文档元数据写入数据库；
- 文档列表、删除、失败重试入口；
- 删除知识库时清理关联 MinIO 文件和文档记录。

**未实现：**

- PDF/DOCX/HTML/图片的真实解析；
- OCR 识别；
- 异步任务队列或可靠后台任务；
- 文本清洗、去重和结构化解析；
- 按知识库策略切片；
- Embedding 生成和向量库存储；
- 处理进度、重试次数、死信和取消任务。

当前 `process_document` 明确留空，文档上传后无法自动完成 `pending → processing → completed` 的完整处理链路。

### 6.6.3 分段管理 🟡

- 分页查看知识库分段；
- 按文档筛选；
- 编辑分段内容；
- 删除分段；
- 展示字数、Token、关键词、命中次数。

页面和数据库结构已具备。编辑分段后 Token 统计只是简单长度估算，无法触发重新向量化；真实 Embedding 尚未完成。

### 6.6.4 检索测试 🔴

计划支持：输入问题、选择检索策略、返回命中文档/分段、相似度、排序、耗时和上下文预览。

当前接口方法和页面已预留，但 `retrieval_test` 仍为 TODO，尚未接入向量数据库。产品上线前必须完成该能力，否则知识库只能作为文件管理功能。

### 6.6.5 知识库验收标准

- 上传文件后状态可追踪，处理失败有明确原因；
- 同一文档重复上传时有去重或版本策略；
- 删除文档同时删除对象存储文件、分段和向量；
- 修改分段后重新生成 Embedding；
- 检索结果稳定返回 Top K，并受相似度阈值过滤；
- Agent 调用知识库时可记录命中片段和检索耗时。

## 7. 核心业务流程

### 7.1 平台初始化流程

1. 准备 MySQL、Redis、MinIO；
2. 执行 Alembic 数据库迁移；
3. 执行 `scripts/init_db.py` 初始化权限、预设角色和默认超管；
4. 管理员登录并修改默认密码；
5. 配置供应商、模型和全局默认配置；
6. 创建知识库、Prompt、工具和 Agent。

### 7.2 Agent 发布流程

1. 创建 Agent 草稿；
2. 配置模型、Prompt、知识库和工具；
3. 在测试页运行多轮测试；
4. 检查模型连接、知识库处理状态和工具可用性；
5. 填写变更说明并发布版本；
6. 发布版本进入未运行状态；
7. 管理员或有权限用户启动 Agent；
8. 运行请求进入 Agent；
9. 记录消息、链路、Token、费用、延迟和结果；
10. 出现问题时停止 Agent 或回滚版本。

### 7.3 知识库处理流程（目标流程）

`上传 → MinIO 持久化 → pending → processing → 文件解析 → 文本清洗 → 分段 → Embedding → 向量库写入 → completed → 可检索`

异常流程：

`任一步失败 → failed + error_message → 用户点击重试 → 清理旧分段/向量 → 重新处理`

### 7.4 模型调用流程

1. 校验用户/API Key 权限；
2. 校验 Agent、模型和供应商状态；
3. 加载当前 Agent 版本配置；
4. 渲染 Prompt 和短期记忆；
5. 执行知识库检索；
6. 根据模型决策调用工具；
7. 调用供应商模型并以 SSE 输出；
8. 记录 Token、费用、耗时、错误和链路；
9. 异步更新统计聚合与告警状态。

## 10. 非功能需求

### 10.1 安全

- JWT Secret 必须从环境变量或密钥管理系统读取，禁止硬编码；
- 生产环境 CORS 必须限定域名，不能使用 `allow_origins=["*"]`；
- 密码使用 bcrypt/Argon2 等强哈希算法；
- API Key、供应商密钥加密或哈希存储；
- 后端所有敏感接口执行 RBAC 权限校验；
- 文件上传校验扩展名、MIME、大小和内容；
- HTTP 工具执行需防 SSRF、内网探测和恶意重定向；
- 日志中不得打印 Token、密码、API Key 原文。

### 10.2 性能

- 列表接口默认分页，不允许无上限查询；
- SSE 首 token 延迟和完整响应耗时应分别统计；
- 文档处理必须异步化，不阻塞上传请求；
- 统计报表优先使用聚合表/缓存，避免每次扫描明细日志；
- Redis 仅用于短期记忆、验证码和热点缓存，持久化记录必须进入数据库。

### 10.3 可用性与可观测性

- 文档、模型、工具、Agent 的状态变化可追踪；
- 任务失败有错误码、错误信息和重试入口；
- 核心 API 记录请求耗时和 trace/request id；
- 关键操作写审计日志；
- MinIO、MySQL、Redis 不可用时应用应提供明确降级/告警，而非静默失败。

### 10.4 兼容性

- 浏览器优先支持现代 Chromium、Safari、Firefox；
- 页面响应式适配桌面和窄屏；
- 后端保持 `/api/v1` 版本前缀，避免前后端协作期间破坏性变更。

- 大规模对话日志查询；
- 前端 Mock/API 切换；
- 安全扫描、依赖扫描、敏感信息扫描。

### 14.4 上线门槛

只有在以下条件全部满足后，才建议从演示/开发状态进入生产试运行：

- P0 项全部关闭或有明确替代方案；
- 知识库能完成真实处理和检索；
- Agent 能完成真实模型调用并生成可审计记录；
- 生产密钥不硬编码，CORS 已收紧；
- 接口权限、API Key、审计日志可验证；
- 核心链路有监控、告警和失败重试；
- 数据备份和恢复演练通过。

## 15. 当前技术债与处理建议

| 技术债 | 优先级 | 建议 |
|---|---|---|
| JWT Secret 硬编码 | P0 | 使用环境变量/密钥管理服务，并在启动时校验长度 |

| CORS `*` | P0 | 按环境配置允许来源，禁止生产全开放 |
| 文档后台任务为空 | P0 | 接入任务队列，补齐解析、切片、Embedding、向量写入 |
| 检索方法 TODO | P0 | 接入向量数据库，实现过滤、Top K、阈值和重排 |
| Agent 启动逻辑 TODO | P0 | 建立运行时实例、状态机、请求入口和资源校验 |
| Provider 连接测试为模拟 | P0 | 按供应商适配器调用真实接口，密钥脱敏 |
| Tool 测试逻辑为占位 | P0 | 增加工具执行器、SSRF 防护、超时和审计 |
| Dashboard/Analytics 无后端 | P1 | 从调用明细异步聚合统计表，补齐查询和导出 |

| API Key/审计/告警无后端 | P1 | 统一系统治理模块和权限校验 |

| 前端大量页面仍依赖 Mock | P1 | 按模块逐步切换真实服务，并保留空态保护 |
