## 1. 项目简介

**辰光 Agent 平台**（`chenguang-agent`）是一个企业内部用于整合、管理各类大模型与 AI Agent 的基础管理平台。

### 核心功能

| 功能域 | 说明 |
|--------|------|
| **用户权限** | 基于 RBAC 的用户 / 角色 / 权限三级管控 |
| **模型管理** | 多厂商模型接入、配置与连通性测试 |
| **Agent 管理** | Agent 全生命周期（创建 → 测试 → 发布 → 版本回滚 → 监控） |
| **Prompt 管理** | Prompt 模板创建、版本化管理 |
| **知识库（RAG）** | 文档上传 → 向量化分段 → 检索测试 |
| **工具管理** | 外部工具注册与测试 |
| **对话日志** | 历史会话查看与详情分析 |
| **数据统计** | 调用量、Token 费用、效果评估多维分析 |
| **系统管理** | API Key 管理、审计日志、告警规则、全局配置 |

## 2. 整体架构

```
+-----------------------------------------------------+
|                    浏览器（前端）                     |
|          React 19 + Vite 7 + TailwindCSS             |
|          路由：react-router-dom v7                    |
|          UI：shadcn/ui (Radix UI + Tailwind)         |
+------------------------+----------------------------+
                         | HTTP/REST (JSON)
                         | Bearer Token
                         v
+-----------------------------------------------------+
|                  后端（API Server）                   |
|           FastAPI 0.135 + Python 3.x                 |
|           Uvicorn ASGI Server                        |
|           前缀：/api/v1                              |
+----------+-------------------------+----------------+
           |                         |
           v                         v
+------------------+    +----------------------------+
|  MySQL 8.x       |    |   Redis                     |
|  异步驱动 asyncmy |    |   验证码缓存                |
|  ORM: SQLAlchemy |    |   redis.asyncio              |
|  迁移: Alembic   |    +----------------------------+
+------------------+
```

**关键设计决策：**

- 前后端**完全分离**，通过 REST API 通信
- 前端支持 **Mock 模式**（`VITE_USE_MOCK=true`），无需后端即可开发 UI
- 后端采用**异步全栈**（async/await + asyncmy + asyncio Redis）
- 统一响应格式 `{code, message, data}`，所有接口保持一致

### 4.3 模块层次约定（四层架构）

每个业务模块遵循固定的四层结构：

```
modules/<name>/
├── model.py        # ORM 模型（数据库表）
├── schema.py       # Pydantic Schema（请求/响应 DTO）
├── repository.py   # 数据访问层（继承 BaseRepository）
├── service.py      # 业务逻辑层
└── api.py          # HTTP 接口层（FastAPI Router）
```

**数据流向：**

```
HTTP Request
  -> api.py        接收请求，参数校验，调用 service
  -> service.py    业务逻辑，调用 repository
  -> repository.py SQL 操作，继承 BaseRepository
  -> model.py      ORM 映射
  -> MySQL
```

**各层职责：**

- **`api.py`**：只负责路由定义、参数提取、调用 service、包装响应；不写业务逻辑或 SQL
- **`service.py`**：所有业务规则在此；调用 repository；抛出 `BizException`
- **`repository.py`**：纯数据操作，继承 `BaseRepository[T]`；不写业务判断
- **`model.py`**：ORM 类定义，继承 `BaseModel`（自带 `id`, `created_at`, `updated_at`）
- **`schema.py`**：Pydantic 模型，`XxxCreate`（请求体）和 `XxxRead`（响应体）

### 4.6 统一响应格式

```json
{
  "code": 200,
  "message": "success",
  "data": { }
}
```

| code 值 | 含义 |
|---------|------|
| 200 | 成功 |
| 400 | 业务参数错误 |
| 401 | 未登录或 token 过期 |
| 500 | 服务器内部错误 |

> HTTP 状态码统一返回 200，业务错误通过 code 字段区分。

**分页响应格式：**

```json
{
  "code": 200,
  "data": {
    "items": [],
    "total": 100,
    "page": 1,
    "page_size": 20
  }
}
```

### 4.7 认证机制 JWT

- **算法**：HS256，**有效期**：30 分钟
- **Payload**：`sub`（用户 ID）、`username`、`exp`、`iat`
- **传递方式**：`Authorization: Bearer <token>`
- **工具文件**：`src/utils/jwt_utils.py`

> ⚠️ `SECRET_KEY` 当前硬编码在 `jwt_utils.py` 中，**生产环境必须移至 `.env`**

**登录验证码流程：**

1. 前端 GET `/api/v1/captcha` → 获取 `{key, image（base64）}`
2. 登录时提交 `{username, password, captcha_key, captcha_code}`
3. 后端从 Redis 取值校验，验证后删除（防重放攻击）

### 4.8 数据库与 ORM

- **数据库**：MySQL 8.x，字符集 `utf8mb4`
- **连接方式**：`mysql+asyncmy://`（异步驱动）
- **连接池**：`pool_size=10, max_overflow=20`
- **会话管理**：每次请求通过 `get_db()` 生成独立 `AsyncSession`，自动提交/回滚

**BaseModel 公共字段（所有 ORM 模型均继承）：**

```
id         BigInteger, PK, autoincrement
created_at DateTime, 自动填充
updated_at DateTime, 自动维护
```

**RBAC 关系：**

```
User ---(user_roles 多对多)---> Role
                                  |
                     (role_permissions 多对多)
                                  |
                                  v
                              Permission
```

**数据库迁移命令：**

```bash
alembic revision --autogenerate -m "描述"  # 生成迁移脚本
alembic upgrade head                        # 执行迁移
alembic downgrade -1                        # 回滚一步
```

### 4.9 Redis 缓存

- **用途**：
  1. **图形验证码**：key 前缀 `captcha:{uuid}`，过期时间 5 分钟。
  2. **模型测试短期会话记忆**：key 前缀 `chat:memory:{conversation_id}`，存储最近多轮对话上下文 JSON 数组。默认保留最近 10 条（5 轮）滑动窗口，过期时间 1800 秒（30 分钟无交互自动释放，不沉淀进永久数据库）。
- **客户端**：`redis.asyncio`，连接池模块级单例
- **注入方式**：`Depends(get_redis_client)`

### 4.11 异常处理

- **`BizException`**：业务异常，`raise BizException(code=400, message="xxx")`
- **全局处理**：未捕获异常返回 `{code: 500}`，Loguru 记录完整堆栈

## 10. 常见约定与注意事项

### 代码约定

| 规则 | 说明 |
|------|------|
| 后端接口统一加 `/api/v1` 前缀 | `main.py` 的 `include_router` 统一加 |
| 所有接口返回 `ResponseSchema[T]` | 不裸返回数据 |
| 业务错误用 `BizException` | 不用 `raise HTTPException` |

| ORM 模型必须继承 `BaseModel` | 保证公共字段 |
| 前端页面只调用门面服务 | 不直接调用 `api/` 或 `mock/` |
| 路径别名 `@/` = `app/src/` | TypeScript 和 Vite 均已配置 |
